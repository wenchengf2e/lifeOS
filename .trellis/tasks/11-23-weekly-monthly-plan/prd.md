# 周度/月度前瞻计划与每日仪式提醒

## Goal

让用户在每个周 / 月开始前，用几分钟写下「本期主题 + 1–3 个重点」，并在每日仪式中持续看到，
作为当天行动的上层坐标。计划数据按周期键存储，为后续周复盘引用预留通路。

## Background

- 每日仪式 `/daily` 目前只有日粒度：今日行动、晚间日记、想法、今日复盘（`src/content/daily.ts`）。
- 周复盘 `/review` 是回顾型四步向导；`reviews` 表与 API 已支持 `week` / `month`，但没有前瞻计划概念。
- 已有的上层坐标都不是周 / 月粒度：
  - 方向卡的「未来 12 个月主题」是年粒度（`src/content/lifeos.ts`）。
  - 五步诊断的「每周动作」是单个目标粒度，且尚未同步到每日仪式（`docs/goal-module-design.md`）。
- 总览 `/` 与 `/daily` 已有 ISO 周、自然月、打卡状态的现成计算，可直接复用（`src/lib/date.ts`、`src/lib/stats.ts`）。

## Requirements

### R1 计划页面

- 新建独立页面 `/plan`，提供周 / 月双轨切换，共用同一套字段结构。
- 默认定位到当前 ISO 周（`YYYY-Www`）和当前自然月（`YYYY-MM`）。
- 支持前后切换周期，并可从历史周期列表进入已写过的周期。
- 顶部导航不新增第 7 项；入口来自每日仪式提醒卡与总览快捷入口。

### R2 计划字段

- 每条计划包含：一句话主题、1–3 个重点。
- 重点是纯文本，不记录完成状态，也不写入清单或目标。
- 不增加「备注」等额外字段；主题和重点都为空时允许保存，用于清空该周期。

### R3 每日仪式提醒

- `/daily` 顶部展示一张提醒卡，以本周计划为主，完整显示主题与重点。
- 月计划压缩为卡片底部一行「本月主题：…」，作为上层坐标。
- 没有内容时显示轻提示和填写入口，不阻塞当天记录。
- 查看历史日期（`?date=YYYY-MM-DD`）时，提醒卡跟随该日期所在周 / 月。

### R4 保存与同步

- 按「用户 + 周期类型 + 周期键」自然键 upsert；重复保存覆盖同一周期。
- 保存成功后刷新 bootstrap 缓存，使每日仪式立即看到新内容。
- 保存失败给出可读错误，不丢当前输入。

### R5 为周复盘预留数据通路

- 计划数据必须能按周期键直接读取，后续周复盘向导可按周取到同一周的计划。
- 本期不改造复盘页面，也不做计划与复盘的双向同步。

## Decisions

- **页面落点**：独立 `/plan` 页，不内嵌每日仪式，不并入 `/review`；顶部导航不加第 7 项。
- **重点形态**：纯文本提醒，不做勾选完成，不与清单联动。
- **每日展示**：一张卡，周计划为主，月计划只留一行主题。
- **历史周期**：支持前后切换和历史列表；历史列表只展示已填写的周期。
- **字段范围**：只做主题 + 最多 3 个重点，不增加备注或其他结构化字段。
- **存储**：复用 `documents`（`module = "plan"`），不新增表或 API；详细设计见 `design.md`。

## Acceptance Criteria

- [ ] `/plan` 可在周 / 月之间切换，并默认落在当前周期。
- [ ] 在当前周填写主题与重点并保存，刷新页面后内容仍在。
- [ ] 周计划与月计划使用各自正确的周期键（`YYYY-Www` / `YYYY-MM`），互不覆盖。
- [ ] 切换周期后能读写对应周期的计划；不存在的周期显示空态而不是报错。
- [ ] 历史周期列表只展示已写过的周期，点击可回到对应周期编辑。
- [ ] 清空主题和重点并保存后，该周期从历史列表消失，每日卡回到空态。
- [ ] `/daily` 顶部显示当前周 / 月计划摘要；两者都为空时只显示轻提示，不遮挡每日模块。
- [ ] `/daily?date=...` 查看历史日期时，提醒卡显示该日期所在周 / 月的计划。
- [ ] 桌面端与移动端布局正常，不出现横向滚动。
- [ ] 保存失败时保留输入并提示；重试成功后状态恢复。
- [ ] `npm run typecheck` 与 `npm run build` 通过。
- [ ] 全量导出 JSON 包含计划数据。

## Out of Scope

- 月复盘页面。
- 周复盘向导读取 / 展示计划（仅保留数据通路）。
- 计划重点与目标、罗盘项目、清单的双向同步。
- 未完成重点自动顺延到下一周期。
- 通知、提醒推送、日历集成。
